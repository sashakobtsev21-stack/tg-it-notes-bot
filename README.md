# tg-it-notes-bot

Автоматизация конвейера для Telegram-канала IT_Notes: сбор новостей → отбор → черновик поста → вычитка в личке → публикация.

## Статус

Весь конвейер собран и проверен живьём на тестовом канале: сбор → отбор → черновик → вычитка (публикуй/правь/отклони) → публикация. Не автоматический — запускается вручную (`npm run review`), пишет в тестовый канал, не в боевой. Открытые пункты — см. «Дальше» внизу.

## Как запустить

```
npm install
npm run collect   # сырой список без дедупа и скоринга
npm run select    # дедуп + скоринг + деление на авто-очередь / на подтверждение / отбой
npm run draft     # то же + черновик поста через Gemini для тем с текстом источника
```

`npm run draft` требует `GEMINI_API_KEY` в `.env` (см. `.env.example`) — бесплатный ключ без карты на aistudio.google.com.

## Вычитка в Telegram (npm run review)

Шлёт черновик владельцу в личку с кнопками «✅ Публикуй / ✏️ Правь / ❌ Отклони» и ждёт нажатия (до 10 минут на тему). «Публикуй» — реально публикует в `TELEGRAM_TEST_CHANNEL_ID`. «Правь» — просит текстом, что поправить, переписывает черновик с учётом инструкции и присылает снова с теми же кнопками (до 3 кругов на тему, дальше пропускает). «Отклони» — просто следующая тема.

Нужны две вещи в `.env`:

1. **`TELEGRAM_BOT_TOKEN`** — в Telegram открыть **@BotFather** → отправить `/newbot` → дать имя и username (должен заканчиваться на `bot`) → он пришлёт токен вида `123456789:AAH...`. Вписать в `.env`.
2. **`TELEGRAM_OWNER_CHAT_ID`** — открыть своего нового бота в Telegram, отправить ему любое сообщение (например «привет»), затем запустить:
   ```
   npm run telegram:whoami
   ```
   Выведет ваш `chat_id` — его тоже в `.env`.

После этого:
```
npm run review
```

**Важно про безопасность тестов:** бот для вычитки должен уметь писать ТОЛЬКО в личку владельцу (`TELEGRAM_OWNER_CHAT_ID`). Пока его никуда больше не добавляли — у него физически нет доступа ни к какой группе или каналу. Когда дело дойдёт до публикации (следующий шаг) — тестировать только на собственном тестовом канале/чате, ни в коем случае не на живой аудитории.

Пороги: score ≥ 7.5 — в очередь на черновик автоматически; 5-7.5 — на подтверждение человеком; < 5 — отбой (не тратим токены на черновик).

### Упрощения текущей версии скоринга (осознанные, не забытые)

- **Формат** темы определяется правилами (ключевые слова), не моделью — дешевле и без ключей на этом шаге; ловит очевидное («X vs Y», «free/open-source»), но может путать литературное «vs.» в заголовке статьи с настоящим сравнением продуктов.
- **Скорость (виральность)** считается только по очкам Hacker News — нет ещё отслеживания роста звёзд GitHub во времени, так что у GitHub-релизов этот показатель всегда 0.
- **Давность** затухает с одним и тем же периодом полураспада (24ч) для всех тем — в разборе предполагалась разная скорость по категориям, здесь пока не размечено.
- Репозитории, тегирующие релизом каждую сборку (например `llama.cpp` — `b10228`, `b10227`...), теперь распознаются и блокируются отдельным правилом («формат: build-tag-noise»), а не просто получают низкий балл.
- **Интересность темы теперь оценивает модель, а не только regex по заголовку.** Замер 02.08: заголовки вида `langchain-core==1.5.2` и `v0.120.1` неотличимы по ключевым словам от значимого релиза — оба получали `формат: generic`. Теперь для тем с текстом источника (если их не убил дешёвый regex-блок и они не настолько старые, что всё равно умрут от давности) отдельный вызов Gemini читает текст и оценивает интересность 0-10 с причиной — проверено вживую: рутинный патч → 1 балл, релиз новой модели → 9. Это заменяет `формат` в формуле, не добавляется к нему.
- **HN-темы теперь тоже можно черновить.** `src/collectors/articleBody.js` — Readability (не голый strip-тегов, обычная веб-страница тащит нав/рекламу/подвал) вытаскивает читаемый текст статьи по ссылке. В пайплайне это обогащение ленивое: только топ-10 HN-тем по первому проходу скоринга без текста источника, не все подряд (веб-фетч дороже JSON API). jsdom при парсинге реальных страниц пробрасывал CSS-warnings в консоль — тысячи строк шума на один фетч; заглушен через `VirtualConsole`.
- **Список репозиториев подрезан 02.08.** SDK-клиенты (anthropic-sdk-python/typescript, openai-python) и langchain-ai/langchain (тегирует релизом каждый суб-пакет отдельно) почти всегда рутинные патчи — заменены на репозитории, где реальные новые возможности выходят чаще (huggingface/transformers, open-webui, ComfyUI, aider).
- **Бесплатный тариф Gemini — 20 запросов В СУТКИ на модель**, не в минуту (замер 02.08, quotaId `GenerateRequestsPerDayPerProjectPerModel-FreeTier`). Черновик и оценка интересности теперь на РАЗНЫХ моделях (`gemini-flash-latest` / `gemini-flash-lite-latest`) — у каждой своя квота, иначе один прогон с оценкой интересности нескольких тем съедал весь дневной лимит черновиков. 20/сутки на модель — реальный потолок, которого хватит на скромный продовый объём, но не на активную разработку в тот же день.

### Черновик поста — что уже работает и что нет

- Модель для текста поста — Gemini через `gemini-flash-latest` (алиас, не конкретная версия: конкретные версии у Google короткоживущие — `gemini-2.5-pro`/`gemini-2.5-flash` протухли за время разработки этого шага). Модели поколения 3.x думают перед ответом, и это тоже тратит `maxOutputTokens` — держим большой запас (2048), иначе ответ обрывается на середине.
- Черновик пишется только по темам, где есть текст первоисточника — GitHub Releases (release notes из атом-фида) и, для лучших HN-тем, вытащенный Readability текст статьи (см. `src/collectors/articleBody.js`).
- **Few-shot по реальным постам канала — механизм готов, содержимого пока нет.** `data/example-posts.md`: вставить посты как есть, разделяя строкой из трёх дефисов (`---`). Пустой файл — не ошибка, просто без few-shot (как сейчас).
- Отдельного шага фактчека (агент, который сверяет черновик с источником построчно) нет — сейчас грунтовка одна: модели явно запрещено писать то, чего нет в тексте источника, и она видит только этот текст. Дополнительная проверка после — уже следующий уровень.
- «Правь» — `reviseDraft()` в `draft.js`, тот же системный промпт + предыдущий черновик + инструкция владельца текстом. Проверено вживую: клик распознан, инструкция поймана, правка учтена корректно.

## Источники (пока)

- **GitHub Releases** — список репозиториев в `src/config/sources.js`
- **Hacker News** — поиск по ключевым словам через открытый Algolia API

Официальные блоги лабораторий (Anthropic/OpenAI/Google) добавлю следующим шагом — там у части нет прямого RSS, нужно сверить точные адреса, чтобы не подсунуть мёртвую ссылку.
