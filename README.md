# tg-it-notes-bot

Автоматизация конвейера для Telegram-канала IT_Notes: сбор новостей → отбор → черновик поста → вычитка в личке → публикация.

## Статус

Готовы сбор и отбор (шаги 1-2 из 5). Дальше: черновик текста, бот с кнопками для вычитки, публикация.

## Как запустить

```
npm install
npm run collect   # сырой список без дедупа и скоринга
npm run select    # дедуп + скоринг + деление на авто-очередь / на подтверждение / отбой
npm run draft     # то же + черновик поста через Gemini для тем с текстом источника
```

`npm run draft` требует `GEMINI_API_KEY` в `.env` (см. `.env.example`) — бесплатный ключ без карты на aistudio.google.com.

Пороги: score ≥ 7.5 — в очередь на черновик автоматически; 5-7.5 — на подтверждение человеком; < 5 — отбой (не тратим токены на черновик).

### Упрощения текущей версии скоринга (осознанные, не забытые)

- **Формат** темы определяется правилами (ключевые слова), не моделью — дешевле и без ключей на этом шаге; ловит очевидное («X vs Y», «free/open-source»), но может путать литературное «vs.» в заголовке статьи с настоящим сравнением продуктов.
- **Скорость (виральность)** считается только по очкам Hacker News — нет ещё отслеживания роста звёзд GitHub во времени, так что у GitHub-релизов этот показатель всегда 0.
- **Давность** затухает с одним и тем же периодом полураспада (24ч) для всех тем — в разборе предполагалась разная скорость по категориям, здесь пока не размечено.
- Репозитории, тегирующие релизом каждую сборку (например `llama.cpp` — `b10228`, `b10227`...), теперь распознаются и блокируются отдельным правилом («формат: build-tag-noise»), а не просто получают низкий балл.

### Черновик поста — что уже работает и что нет

- Модель — Gemini через `gemini-flash-latest` (алиас, не конкретная версия: конкретные версии у Google короткоживущие — `gemini-2.5-pro`/`gemini-2.5-flash` протухли за время разработки этого шага). Модели поколения 3.x думают перед ответом, и это тоже тратит `maxOutputTokens` — держим большой запас (2048), иначе ответ обрывается на середине.
- Черновик пишется **только** по темам, где есть текст первоисточника (сейчас — release notes из GitHub Releases). По HN-темам черновик пока не пишется вообще: там есть только заголовок, а писать пост без текста источника — точно путь к придуманным фактам. Нужен отдельный шаг «зайти по ссылке и вытащить текст статьи» — это не тривиально (HTML разных сайтов устроен по-разному), пока не делал.
- Нет ещё few-shot по вашим реальным постам — стиль сейчас держится только на текстовых правилах из брифа. Как пришлёте 5-10 своих любимых постов текстом — добавлю, станет больше похоже на голос канала.
- Отдельного шага фактчека (агент, который сверяет черновик с источником построчно) нет — сейчас грунтовка одна: модели явно запрещено писать то, чего нет в тексте источника, и она видит только этот текст. Дополнительная проверка после — уже следующий уровень.

## Источники (пока)

- **GitHub Releases** — список репозиториев в `src/config/sources.js`
- **Hacker News** — поиск по ключевым словам через открытый Algolia API

Официальные блоги лабораторий (Anthropic/OpenAI/Google) добавлю следующим шагом — там у части нет прямого RSS, нужно сверить точные адреса, чтобы не подсунуть мёртвую ссылку.
